# Aurellix 集团官网开发经验总结与未来支付通道扩展指南

> 本文档沉淀了 2026-11-16 至 2026-11-17 期间 **Aurellix 集团官网** 改版、多业务拆分、上线部署与合规口径调整的工程经验，方便后续新增支付通道、扩展覆盖国家或切换子站域名时快速定位修改点并零回归上线。

---

## 一、项目结构与发布工作流

1. **双目录协作原则（`build_v2/` → `build/`）**
   - `AurellixPay_new_website/build_v2/`：开发与验证主目录。所有 HTML、CSS (`static/v2.css`)、公共 JS (`static/v2-common.js`) 与 SVG 地图 (`static/world_map.svg`) 修改均先在此目录完成。
   - `AurellixPay_new_website/build/`：线上部署目录（Cloudflare Pages 连接 GitHub 仓库 `EastAndWeast/pay` 的 `dev` 分支，构建命令留空，输出目录 `build`）。
   - **发布铁律**：改动在 `build_v2/` 通过全量验证后，必须完整镜像覆盖 `build/` 再提交推送 `origin/dev`，避免只改 `build_v2/` 导致线上未生效。

2. **6 个核心页面职责**
   - `index.html`：集团官网主入口（Hero 展示、4 业务能力图文窗、4 步开通、行业摄影墙、RWA 平台区、4 项合规资质、Slogan CTA）。
   - `fx.html`：全球收付单板块切换页（`01 全球收款 22 国 VA`、`02 全球付款与电子钱包`、`03 实时换汇与合规结汇`、`04 B2B 外贸解决方案`）。
   - `otc.html`：全球承兑（法币 ⇄ 稳定币清结算）及 26 国多币种清算矩阵（注意：对外文案禁用 `"OTC"` 字样，仅保留文件名兼容已有链接）。
   - `coverage.html`：4 业务联动交互世界地图（`01 全球收款` / `02 全球付款` / `03 全球承兑` / `04 全球收单`）、36 国双渠道矩阵及 94 国收单目录。
   - `privacy.html` / `terms.html`：中英双语 8 章企业级隐私政策与服务条款（无更新时间、统一邮箱 `info@aurellix.com`）。

## 二、未来新增支付通道 / 覆盖国家修改清单

当您后续拿到新的合作银行通道、电子钱包或新增国家时，按业务线对应修改以下数据数组（无需重写页面结构）：

| 业务线 | 核心数据位置（`build_v2/`） | 需同步的地图 / 统计位 |
| :--- | :--- | :--- |
| **01 · 全球收款 (本地 VA)** | • `fx.html` → `VA_MARKETS`（第 905 行）<br>• `coverage.html` → `VA_COV_MARKETS`（第 935 行） | • `coverage.html` → `BIZ_MAP_META.collect`（第 979 行）<br>• 若突破 22 国，同步更新 `index.html`、`fx.html`、`coverage.html` 及 `v2-common.js` 中的 `22` / 区域计数 |
| **02 · 全球付款 (本地银行 & 电子钱包)** | • `fx.html` → `EWALLETS`（第 955 行）<br>• `coverage.html` → `PAYOUT_HUB_MARKETS`（第 960 行） | • `coverage.html` → `BIZ_MAP_META.payout`<br>• 若新增钱包国家或币种，同步更新 `33+` / `11 国 19 种` 文案 |
| **03 · 全球承兑 & 实时换汇** | • `fx.html` → `FX_CURRENCIES`（第 932 行，20 种实时换汇币种）<br>• `otc.html` → `CURRENCIES`（第 711 行，26 国双向承兑矩阵）<br>• `coverage.html` → `CHANNEL_MARKETS`（第 692 行，36 国双渠道对比） | • `coverage.html` → `BIZ_MAP_META.convert`<br>• 同步更新各区块地区筛选按钮括号内的计数与 `26 国` / `36 国` 口径 |
| **04 · 全球收单 (卡 / 本地 APM / 稳定币)** | • `coverage.html` → `countriesData`（第 743 行） | • `BIZ_MAP_META.acquiring` **自动从 `countriesData` 读取**（`isCore: true` 为深蓝核心国，其余为扩展蓝）<br>• 若总国家数超过 `94`，同步更新 `index.html`、`coverage.html`、`v2-common.js` 中的 `94+` 描述与大区 Tab 计数 |

> **地图着色提示**：`static/world_map.svg` 的国家路径 ID 为 **小写 ISO-2 位国家码**（如 `us`、`gb`、`sg`、`br`）。对于欧元区 (`eu`) 等聚合节点，地图数组必须展开为实体成员国代码（如 `['de','fr','it','es','nl','be','lu','ie','at','pt','fi','gr']`）才能在地图上点亮。

## 三、本轮官网研发沉淀的 6 条实战经验与避坑规范

1. **合规与对外口径红线（必须严格过滤）**
   - 禁止出现任何竞品参考站点名称。
   - **禁止出现 `OTC` 字样**：承兑业务统一使用 `全球承兑` / `Global Conversion` / `Fiat ⇄ Stablecoin Clearing`。
   - **禁止出现 `PYUSD`**：收银台代币、合规卡与承兑支持列表仅保留 `USDT`、`USDC`（及 `EURC`）。
   - **RWA 命名统一为 `RWA 平台` / `RWA 官网`**：避免使用 `官网子站` / `子网站` / `Sub-site`。
   - **官方联系邮箱统一为 `info@aurellix.com`**，隐私与条款页不标注「最近更新时间」。

2. **静态 HTML 文案与 JS 双语字典必须同步**
   - 仅改 `PAGE_TRANSLATIONS` / `COMMON_TRANSLATIONS` 会导致首屏未执行 JS 前短暂闪现旧文案；仅改 HTML 标签内容则会被 `applyLang()` 覆盖。修改任意 `[data-i18n]` 文本时，务必 **HTML 默认英文 + `en` 字典 + `zh` 字典** 三处同步。
   - 若带 `[data-i18n]` 的按钮或链接内嵌 FontAwesome 图标，必须把 `data-i18n` 放在内层 `<span>` 上，或给 `<i>` 加上 `data-keep-icon="true"`，否则 `el.textContent = ...` 会把图标抹掉。

3. **外部子站链接（如 VitePress 文档站）上线前先实测路由**
   - `https://docs.rail.aurellix.com/` 为 VitePress `v1.6.4` 构建的 SPA，未部署 `/zh/` 路由，直接拼接 `/zh/` 会触发客户端 `404 PAGE NOT FOUND`。外部链接不要凭猜测拼接语言后缀，应先用 `curl` 或浏览器实测确认可用后再写入 `v2-common.js`。

4. **多业务交互地图切换必须「先全清、再重绘」**
   - 在 `coverage.html` 中每次切换 `collect` / `payout` / `convert` / `acquiring` 时，必须先清除 SVG 内所有 `.map-core-active`、`.map-global-active` 及旧 `onclick`，再为新业务重新着色并绑定卡片定位事件，防止不同业务线的国家高亮互相残留。

5. **导航高亮由 JS 按路由 + 哈希 + Tab 状态动态驱动**
   - 不要在单个子页静态写死多个 `aria-current="page"`（曾导致从「解决方案」跳入 `fx.html#fx-b2b` 或 `otc.html#solution` 时误高亮「产品服务」）。统一由 `v2-common.js` 的 `updateNavHighlight()` 结合路径、`location.hash` 和 `fx.html` 的 Tab 回调维护状态，且查找 DOM 时使用 `.querySelector(...)` 替代 CSS `:has()` 以保证全浏览器与测试环境兼容。

6. **每次更新后执行「自动化校验 + 静态扫描 + 镜像同步」闭环**
   - 修改 `build_v2/` 后先跑 `verify_v2.js` 校验脚本（当前已覆盖 **1319 项断言**：6 页零 JS 报错、零违禁词、无旧汇率/旧邮箱/PYUSD/OTC、全部内部 `#hash` 锚点有效性、全量中英文 `data-i18n`、4 业务地图切换与 SVG 着色、默认展开状态等）。
   - 验证 `PASSED` 且 `FAILED: 0` 后再镜像覆盖 `build/`，用本地预览服务器确认各页 `200 OK` 并推送 `origin/dev`。
